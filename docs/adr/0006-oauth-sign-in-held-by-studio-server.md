# OAuth Sign-ins are held by the Studio Server, in SQLite, per Connection

For OAuth-protected MCP Servers the Studio Server runs the whole MCP SDK client auth flow (discovery, dynamic client registration, PKCE, refresh) and receives the authorization redirect on its own loopback port; the browser only opens the authorization URL. Tokens and the client registration are stored in SQLite (`oauth_credentials`, one row per Connection, cascade-deleted with it) and bound to the MCP Server URL they were issued for, so editing a Connection's URL never presents its tokens to another server. They never cross the WebSocket and are never logged. We chose plain SQLite next to the rest of Studio's local data over the OS keychain (no cross-platform native dependency for a Bun-only tool, see ADR-0004) and over browser storage (would expose tokens to the page and lose them across browsers); the database file is therefore as sensitive as the tokens in it.

Sign-out and URL changes retire the credential generation so in-flight exchanges cannot restore a discarded Sign-in. Each Session can cancel its own wait or reconnect; concurrent Sessions share one SDK authorization flow per generation with its own lifetime. Only browser-allowed, connecting Sessions receive approval links, including late joiners. Connected Sessions may share refresh, but fail promptly with a sanitized authentication error if the flow requires browser approval; reconnect starts sign-in. This preserves shared rotating-token refresh without opening browser approval during a Call. Browser approval cancels when the last waiter leaves, while in-flight token responses finish and persist unless their credential generation was retired. Each auth endpoint request has a 30-second deadline independent of any Session, so a hung endpoint cannot hold the shared flow indefinitely. OAuth response bodies and response metadata stay inside that flow, while MCP frame capture remains enabled with known OAuth secrets redacted from log data. New data directories use mode 0700 and database files are restricted to 0600 on every open.
